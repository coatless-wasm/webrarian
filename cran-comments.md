## Notes for the CRAN team

**License.** webrarian is released under AGPL-3. `LICENSE.note` adds a section 7
additional permission for the files webrarian generates (an output exception). It
grants rights and restricts none, so the License field states AGPL-3 alone; WRE
§1.1.2 reserves `+ file LICENSE` for restrictions and license templates.

**Vendored browser bundle.** `inst/viewer/exlibris-r.js` and `exlibris-r.css`
are a prebuilt, minified JavaScript and CSS bundle: the in-browser workspace
that the sites generated by `bind()` and `collection_mirror()` load. R never
executes or parses them; `bind()` and `collection_mirror()` copy them into the
sites they write and stop with an error if they are missing. Their source is
the exlibris project (https://github.com/coatless-wasm/exlibris), at the commit
`inst/viewer/PROVENANCE.json` records.

Because a minified file cannot be reviewed by reading it, the package ships the
provenance and attribution alongside it:

* `inst/viewer/THIRD-PARTY.md` lists every npm package that contributes bytes to
  the bundle, with version and license, followed by each package's own license
  files. exlibris's build generates that list from the bundler's metafile and
  appends the notices a metafile cannot see: the code nested inside
  `jszip.min.js` and the terminal notice xterm.js keeps.
* `inst/viewer/PROVENANCE.json` records the exlibris commit the bundle was built
  from and a SHA-256 for each vendored file. The package's tests re-hash the
  installed files against it.
* `inst/viewer/LICENSE.webR.md` carries the notice for the embedded webR
  JavaScript client, and `inst/viewer/EXCEPTION.md` the exlibris runtime
  exception.
* `LICENSE.note` summarizes the above.

Every copyright holder of bundled code is credited with a `cph` role in
`Authors@R` and listed, with the notice the code carries, in `inst/COPYRIGHTS`
(named in the `Copyright` field).

**The webR runtime.** The WebAssembly build of R is not part of the package.
`bind()` downloads it into the user's cache (`tools::R_user_dir("webrarian",
"cache")`) and copies it into the site unless the collection sets
`build.bundle-engine: false`, in which case the site loads it from
https://webr.r-wasm.org. The cache keeps the three engine versions used most
recently and removes older ones.

**Network use during checks.** `R CMD check --as-cran` runs the `\donttest{}`
examples, and two of them use the network: `check_inventory()` queries the webR
package repository and, to compare package versions, CRAN (through
`utils::available.packages()` with a 20-second limit; the option
`webrarian.cran_repo = FALSE` skips that request), and `diagnose_collection()`
probes the repository, GitHub and the webR CDN. Both report an unreachable
service in their result instead of failing. Examples that download the webR
engine (about 40 MB) or need Docker are in `\dontrun{}`, or run only in an
interactive session with a network connection. Tests that use the network,
Docker or a browser are skipped on CRAN, and the test suite sets
`webrarian.cran_repo = FALSE` in `tests/testthat/setup.R`, so no test contacts
CRAN.

**Default paths.** Functions that write (`catalog()`, `bind()`,
`acquire_package()`, `settings_set()` and the like) take `path = "."`, like
`pkgdown::build_site()`: webrarian is a project tool, run from inside a
collection, and every function except `catalog()` first checks that `path` is
inside a collection. Examples and tests write only under `tempdir()`, and the
vignettes write nothing.

**Docker** is needed only to compile local or GitHub packages to WebAssembly,
never for prebuilt packages and never during checks. It is listed in
`SystemRequirements`, with the Quarto command line tool that builds the
vignettes.
